# 日志规范（对标大厂做法）

> 本规范用于统一项目日志的编写方式，后续所有开发都必须遵循。

## 1. 日志级别

| 级别 | 使用场景 | 示例 |
|---|---|---|
| **DEBUG** | 开发调试的详细信息 | 中间变量、完整数据 |
| **INFO** | 关键业务事件 | 收到请求、分流结果、工具调用、对话完成 |
| **WARNING** | 可恢复的异常 | LLM 调用失败重试、低置信度兜底、降级 |
| **ERROR** | 不可恢复的异常 | 工具执行失败、数据库连接失败 |
| **CRITICAL** | 系统级故障 | 服务不可用 |

**原则：ERROR 及以上必须记录异常堆栈（`logger.error(..., exc_info=True)`）。**

## 2. 日志格式（结构化 JSON）

每条日志是一行 JSON，固定字段：

| 字段 | 说明 |
|---|---|
| `ts` | 时间戳（本地时间，毫秒） |
| `level` | 级别 |
| `logger` | 模块名 |
| `trace_id` | 一次请求/对话的唯一 ID |
| `msg` | 日志消息（一句话，不含变量） |
| 业务字段 | 通过 `extra={...}` 传入，如 `intent`、`tools`、`confidence` |
| `exc` | 异常堆栈（仅 ERROR 时） |

**示例输出**：

```json
{"ts": "2026-09-07T10:46:34.902", "level": "INFO", "logger": "router", "trace_id": "demo-123", "msg": "分流结果", "intent": "simple", "confidence": 0.9, "source": "llm", "query": "笔记本保修期"}
```

## 3. trace_id 贯穿

- 每次对话请求在入口（`chat` 接口）设置 `trace_id`（用 `thread_id`）
- 该请求后续所有日志（router、agent、工具）自动带上同一个 `trace_id`
- 排查问题时，用 `trace_id` 过滤日志即可还原一次请求的完整链路

## 4. 埋点位置（必须打日志的地方）

| 位置 | 级别 | 关键字段 |
|---|---|---|
| 请求入口 / 出口 | INFO | thread_id、msg_len / reply_len |
| 分流结果 | INFO | intent、confidence、source（rule/llm） |
| Agent 工具调用 | INFO | tools（工具名列表） |
| 外部调用（LLM/embedding/DB） | INFO | 调用目标、耗时 |
| 降级 / 兜底 | WARNING | 降级原因 |
| 异常 | ERROR | 异常堆栈 |

## 5. 使用示例

```python
from app.utils.logger import get_logger

logger = get_logger(__name__)

# 关键事件（INFO + 业务字段用 extra）
logger.info("分流结果", extra={"intent": "simple", "confidence": 0.9})

# 可恢复异常（WARNING）
logger.warning("分流失败，兜底走 complex", extra={"error": type(e).__name__})

# 不可恢复异常（ERROR + 堆栈）
logger.error("工具执行失败", extra={"tool": name}, exc_info=True)
```

## 6. 禁止事项

1. **不要用 f-string 拼接业务变量进 msg** —— 用 `extra` 传变量，保持 `msg` 简洁（方便检索和统计）。
   ```python
   # ❌ logger.info(f"分流结果: intent={intent}")
   # ✅ logger.info("分流结果", extra={"intent": intent})
   ```
2. **不要记录敏感信息** —— API key、密码、完整手机号等必须脱敏。
3. **不要在循环里打 DEBUG** —— 会刷屏。
4. **不要裸 print** —— 统一走 logger。

## 7. 后续演进方向（接入日志平台时）

- 结构化 JSON 已为 ELK / Loki / 阿里云 SLS 等日志平台做好准备，直接采集即可
- 补充 Metrics（指标）和 Tracing（链路追踪），与日志构成可观测性三大支柱
